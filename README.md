# pico-irq

Interrupt-driven button-to-buzzer demo for the Raspberry Pi Pico 2, generating two distinct tones (dot/dash) from two physical buttons using GPIO IRQs with software debouncing.

## Overview

This project demonstrates how to use the Raspberry Pi Pico SDK's GPIO interrupt API to react to button presses without polling. Two push buttons are wired to falling-edge interrupts; each press queues a flag that the main loop turns into a square-wave tone driven on a buzzer pin. The handler applies a 100 ms debounce window to filter mechanical contact bounce.

## Features

- Falling-edge GPIO interrupt handling via `gpio_set_irq_enabled_with_callback`
- Per-button software debouncing using `absolute_time_t` timestamps (100 ms window)
- Two distinct tones generated by bit-banging a square wave on a GPIO pin:
  - Button 1 → 1 kHz tone, 100 ms duration
  - Button 2 → 6 kHz tone, 300 ms duration
- Internal pull-ups enabled on both button inputs
- Volatile flag pattern to safely communicate between ISR and main loop

## Tech Stack

- **Language:** C (C11)
- **SDK:** Raspberry Pi Pico SDK 2.2.0
- **Hardware:** Raspberry Pi Pico 2 (RP2350), two push buttons, passive buzzer
- **Build system:** CMake 3.12+, GNU Arm Embedded Toolchain 14.2

## Architecture

```
main/
├── main.c           # Application code: ISR, tone generation, main loop
└── CMakeLists.txt   # Executable target linking pico_stdlib
CMakeLists.txt       # Top-level project, SDK import
```

The ISR (`gpio_callback`) is registered for both buttons and dispatches based on the source GPIO. Tone generation runs in the main loop to keep the ISR short.

## Pinout

| Signal  | GPIO |
| ------- | ---- |
| Button 1 | 15   |
| Button 2 | 14   |
| Buzzer  | 16   |

## How to Build

Requires the [Pico SDK](https://github.com/raspberrypi/pico-sdk) and the ARM toolchain configured (e.g. via the official VS Code extension).

```bash
mkdir build && cd build
cmake ..
make
```

Flash the resulting `pico_emb.uf2` to the Pico 2 in BOOTSEL mode.
